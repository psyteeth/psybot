# Psybot — Telegram-бот «Психостоматология»

Бот для тест-драйва: разбирает вопросы по отношениям (схема A-B-C-D-E), помогает
с вопросом по зубам (шаблонный сценарий) и рассказывает о концепции
психостоматологии по данным Google-таблицы. Стек: Python 3.11+,
python-telegram-bot v21 (async, long polling), Claude API (`anthropic`), Google
Sheets (`gspread`), состояние — SQLite.

## Структура проекта

```
psybot/
  bot/
    main.py          — сборка Application, запуск long polling
    config.py         — переменные окружения, лимиты, константы
    db.py              — SQLite: пользователи, сессии, лимиты
    llm.py             — обёртка над Claude API (prompt caching)
    sheets.py          — логирование в Google Sheets + кэш таблицы концепции
    keyboards.py       — инлайн-клавиатуры
    handlers/
      menu.py          — /start, главное меню, текстовый фолбэк
      teeth.py          — ветка «Зубы»
      relationships.py  — ветка «Отношения» (A-B-C-D-E)
      concept.py         — ветка «Концепция»
  assets/teeth_chart.jpg — схема FDI
  deploy/                — systemd unit, deploy.sh, backup_db.sh
  data/                   — bot.db (не в git) и бэкапы
  requirements.txt
  .env.example
```

## Переменные окружения

См. `.env.example`. Все секреты — только через окружение, никогда не в коде.

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота из BotFather |
| `ANTHROPIC_API_KEY` | ключ Claude API |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | JSON сервисного аккаунта Google, строкой |
| `LOG_SPREADSHEET_ID` | таблица для логов разговоров |
| `CONCEPT_SPREADSHEET_ID` | таблица концепции (только чтение) |
| `ADMIN_CHAT_ID` | chat_id для уведомлений админу (опционально) |

## Запуск локально

```bash
cd psybot
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить секреты
.venv/bin/python -m bot.main
```

Без `GOOGLE_SERVICE_ACCOUNT_JSON` бот работает, но логирование в Sheets и
таблица концепции отключены (сбой Google API не роняет бота — см. `bot/sheets.py`).
Без `ANTHROPIC_API_KEY` LLM-вызовы упадут исключением — нужен реальный ключ для
веток «Отношения»/«Концепция» и для разбора текстового номера зуба.

## Модели

- Ветки «Отношения» и «Концепция»: `claude-sonnet-5`.
- Меню/маршрутизация и ветка «Зубы»: `claude-haiku-4-5-20251001` (используется
  только для разбора текстового описания зуба и классификации приветствия —
  большая часть сценария «Зубы» вообще без LLM).
- Системные промпты кэшируются через `cache_control: ephemeral` (`bot/llm.py`).

## Лимиты (константы в `bot/config.py`)

- «Отношения»: 3 полных разбора на пользователя, внутри разбора — 40
  сообщений (после чего бот мягко сворачивает к шагу E).
- «Зубы»: 10 сессий на пользователя.
- «Концепция»: 30 сообщений на пользователя за весь тест-драйв.

Счётчик разборов/сессий считает каждую **начатую** сессию (включая брошенные
на середине или прерванные из-за признаков насилия), а не только доведённые
до конца — иначе лимит можно обойти, просто не завершая разбор. Это
допущение; если нужно считать только завершённые — поменять на подсчёт
`WHERE completed=1` в `bot/db.py`.

### Где хранится счётчик и как посмотреть/поменять лимит вручную

Текущее «сколько использовано» — в SQLite (`data/bot.db`, считается по
количеству созданных сессий/сообщений), это не видно снаружи и руками не
редактируется.

Сам **лимит** (сколько разрешено) — глобальный дефолт из `bot/config.py`,
но может быть переопределён персонально, без правки кода:

- Лист **«Лимиты (ручные)»** в таблице логов (`LOG_SPREADSHEET_ID`):
  колонки `user_id | ветка (Отношения/Зубы/Концепция) | лимит | комментарий`.
  Вписал строку — бот подхватит её в течение 5 минут
  (`LIMIT_OVERRIDES_REFRESH_SECONDS` в `bot/config.py`) и будет считать лимит
  этого пользователя по этой ветке равным указанному числу, независимо от
  глобальной константы.
- Команда **`/limits <user_id>`** в Telegram (доступна только тому, чей
  chat_id указан в `ADMIN_CHAT_ID`) — показывает по всем трём веткам: лимит,
  сколько использовано, сколько осталось. `user_id` берётся из колонки
  `user_id` любого листа таблицы логов.

Логика — в `bot/limits.py`.

## Открытые вопросы (см. ТЗ, помечено «уточнить у заказчика»)

- Лимит сообщений в ветке «Концепция»: сейчас 30 за всё время, легко
  поменять в `bot/config.py::LIMIT_CONCEPT_MESSAGES`.
- Точная формулировка сообщения при признаках насилия/угрозы в «Отношениях»
  (сейчас — `CRISIS_TEXT` в `bot/handlers/relationships.py`).
- Условие «позиции не сошлись» в споре по концепции: реализовано как два
  подряд определённых LLM спорных сообщения (`DISPUTE_STREAK_THRESHOLD` в
  `bot/handlers/concept.py`) — после этого бот предлагает написать
  @psyteeth и (если задан `ADMIN_CHAT_ID`) уведомляет админа.

Модуль «Скрытая потребность + SET-панчлайн» (`bot/hostility.py`, дополнение к
ТЗ) — свои открытые пункты:

- Контакты помощи при суицидальном кризисе: сейчас `@psyteeth` + линия
  8-800-2000-122 (реальная бесплатная круглосуточная линия РФ), см.
  `SELF_HARM_TEXT` в `bot/hostility.py` — заказчик может захотеть другие/
  дополнительные контакты.
- «Дверь назад» в разбор: реализовано как «редко, на усмотрение модели» —
  промпт прямо просит не добавлять её в большинстве ответов (эталонные
  примеры из ТЗ сами её не используют). Если нужно «всегда» или «никогда» —
  правится в `PUNCHLINE_SYSTEM` в `bot/llm.py`.
- Мат: бот зеркалит, только если пользователь уже матерился в этой сессии
  (простая regex-проверка `PROFANITY_RE`, не LLM) — реализовано как в ТЗ.
- Включать ли модуль на шаге D «Отношений»: сделано «нет» (по умолчанию из
  ТЗ) — сопротивление на D считается материалом разбора, не выпадом; кризис
  (суицидальный) при этом всё равно проверяется всегда. Переключается через
  `skip_hostility=True` в вызове `hostility.precheck(...)` внутри
  `d_question` в `bot/handlers/relationships.py`.

## Что проверено локально (симуляция без реального Telegram/Claude)

- Полный проход «Отношений» A → E со всеми восемью оспариваниями, запись
  всех колонок в SQLite (число_сообщений считается верно).
- Признаки насилия на шаге A обрывают разбор, ведут к специалисту, лог
  помечен `exit_step=crisis`.
- Лимит 3 разбора блокирует 4-ю попытку с нужным текстом.
- «Зубы»: номер словами → подтверждение через инлайн-кнопки; невалидный
  номер вне схемы FDI отклоняется с просьбой попробовать снова; острые
  симптомы (сильная боль/отёк/температура/кровотечение) обрывают сценарий
  на любом шаге.
- «Концепция»: ответ с релевантным листом таблицы, эскалация при споре,
  строки в Sheets формируются с верными колонками.
- Сбой Google Sheets (нет `GOOGLE_SERVICE_ACCOUNT_JSON`) не роняет бота —
  запись просто логируется как потерянная.

Не проверено (нужен реальный прогон с настоящими токенами): фактическое
качество ответов Claude, реальная запись в Google Sheets, поведение
long polling под Telegram.

## Деплой на VDS (Ubuntu 22.04, Weecere, Fremont CA)

**Реально развёрнуто и работает** на 69.40.207.79. Ниже — как именно, включая
отличия от изначального плана (упирались в ограничения sudo на этой сессии,
решили без root, где возможно).

### 1. Безопасность сервера (сделано)

- Root-пароль остался прежним (сессия, в которой его меняли, не смогла
  выполнить смену — см. заметку ниже); root по SSH и вход по паролю
  **отключены** (`PermitRootLogin no`, `PasswordAuthentication no` в
  `/etc/ssh/sshd_config`), проверено явным тестом.
- Пользователь `psybot` — вход только по SSH-ключу (пара сгенерирована в
  `psybot/.deploy_secrets/psybot_admin_key`, **не коммитить**), с ограниченным
  `NOPASSWD`-sudo только на `systemctl {start,stop,restart,status} psybot` и
  `journalctl -u psybot`.
- `ufw` включён, разрешён только OpenSSH.
- ⚠️ Root-пароль всё ещё тот, что был изначально (менять пока не удалось из-за
  ограничений sudo в сессии деплоя) — валиден для веб-консоли хостера. Сменить
  вручную через консоль (`passwd`), когда будет удобно.

### 2. Python 3.11 — без root, через `uv`

Пакетный менеджер apt требовал root, которого не стали расширять сверх
необходимого. Вместо `apt install python3.11`:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # ставится в ~/.local/bin, без sudo
uv python install 3.11                             # готовый бинарник, без компиляции
```

### 3. Код — приватный GitHub-репозиторий + деплой-ключ

Репозиторий: `git@github.com:psyteeth/psybot.git` (приватный). На сервере —
свой read-only deploy key (`~/.ssh/psybot_deploy_key` у пользователя `psybot`,
добавлен в Settings → Deploy keys репозитория без права записи), настроен
через `git config core.sshCommand` в `/home/psybot/psybot/.git/config`. Код в
`/home/psybot/psybot/` (не `/opt/psybot` — `/opt` root-only, `psybot`
пользователем без root не пишет туда).

```bash
psybot/deploy/deploy.sh   # git pull + pip install + restart, см. п.6
```

### 4. Секреты

`.env` на сервере — не в git (в `.gitignore`), скопирован туда напрямую
(`scp`), права `600`, владелец `psybot`.

### 5. Автозапуск — user-level systemd, не системный

`/etc/systemd/system/` тоже root-only. Вместо системного сервиса — юнит
пользователя `psybot`:

```bash
# уже сделано:
mkdir -p ~/.config/systemd/user
cp deploy/psybot.service ~/.config/systemd/user/psybot.service
systemctl --user daemon-reload
systemctl --user enable --now psybot
loginctl enable-linger psybot   # чтобы сервис жил без активной SSH-сессии — сработало без root
```

Важно: юнит **не использует** `EnvironmentFile=` — сложный JSON-ключ сервис-аккаунта
с кавычками и `\n` внутри ломается парсером systemd (`MalformedError: No key
could be detected`). Секреты грузятся самим ботом через `python-dotenv`
(`bot/config.py`), это уже работает и без `EnvironmentFile`.

Управление:
```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)   # нужно при заходе не через полноценный логин-шелл
systemctl --user status psybot
journalctl --user -u psybot -f
```

### 6. Обновление

```bash
psybot/deploy/deploy.sh
```
(`git pull` на сервере через deploy key, `pip install -r requirements.txt`,
`systemctl --user restart psybot`. Запускать после `git push` изменений в `main`.)

### 7. Бэкап SQLite (сделано)

Cron пользователя `psybot` на сервере:
```
0 3 * * * /home/psybot/psybot/deploy/backup_db.sh
```
Бэкапы — в `/home/psybot/psybot/data/backups/bot-YYYY-MM-DD.db`, хранятся 14 дней.

### 8. Память

1 ГБ RAM, из которых на сервере уже занято другим процессом (`vibe-trading`,
не связан с psybot — тот же VDS используется для нескольких ботов). Psybot
сам по себе — около 50 МБ в простое. Таблица концепции кэшируется в памяти
процесса (обновление раз в час, `bot/sheets.py::ConceptStore`), не грузится
целиком в каждый запрос к LLM. Своп уже настроен (2 ГБ) — на сервере он был
ещё до этого деплоя.

### Что осталось (не сделано в эту сессию)

- Сменить root-пароль (см. п.1) — нужен root-доступ, который сам себе я не
  могу выдать.
- Опционально: расширить sudo для `psybot` (например, до `apt-get`), если
  понадобится ставить системные пакеты в будущем — сейчас `psybot` работает
  почти без sudo (только управление своим systemd-юнитом).
